# AI YouTube Thumbnail Generator

Generate studio-quality YouTube thumbnails from a single headshot. Upload a photo, describe the mood you want, and the app uses AI image models to produce ready-to-upload 1280×720 thumbnails — auto-cropped into **16:9 (video)**, **9:16 (Shorts)**, and **1:1 (square)** variants by the CDN.

Built as a full-stack app: a **FastAPI** backend with JWT authentication and a **React + TypeScript** frontend with a real-time preview of every thumbnail as it is generated.

---

## ✨ Features

- 🔐 **User accounts** — sign up / login with bcrypt-hashed passwords and JWT access tokens (30 min expiry)
- 🖼️ **Headshot upload** — drag & drop image upload, stored on the ImageKit CDN
- 🎨 **AI thumbnail generation** — pluggable image providers with automatic fallback:
  - Hugging Face `FLUX.1-schnell` / `FLUX.1-Kontext-dev` (default primary)
  - Google Gemini (`gemini-2.5-flash-image`, "Nano Banana") — supports image-to-image using your headshot as the visual reference
  - Pollinations `flux` (free, no API key) — default fallback
  - OpenAI (optional)
- ⚡ **Real-time progress** — Server-Sent Events (SSE) push each result to the browser the moment it finishes; no page refreshes
- 🔄 **Background jobs** — 1–3 thumbnails per job, generated concurrently so the API responds instantly
- 📐 **Automatic output variants** — YouTube / Shorts / Square transform URLs generated by ImageKit at the CDN edge (no extra uploads)
- 🧭 **Polished React UI** — dashboard, guided 2-step create flow, live job page, protected routes, form validation (React Hook Form + Zod)

## 🚀 Getting Started

### 1. Prerequisites

- **Python 3.11+**
- **Node.js 18+**
- A free **ImageKit** account (for image hosting + CDN variants)

### 2. Backend setup

```bash
cd BACKEND
python -m venv venv              # create virtual environment
source venv/bin/activate         # macOS/Linux  (venv\Scripts\activate on Windows)
pip install -r requirements.txt
```

Create a `.env` file inside `BACKEND/`:

```env
# --- Image providers ---
IMAGE_PROVIDER=huggingface       # huggingface | gemini | pollinations | openai
IMAGE_PROVIDER_FALLBACK=pollinations

# Hugging Face (needed if IMAGE_PROVIDER=huggingface)
HF_TOKEN=your_huggingface_token
HF_MODEL=black-forest-labs/FLUX.1-schnell
HF_PROVIDER=fal-ai

# Google Gemini (needed if IMAGE_PROVIDER=gemini)
GEMINI_API_KEY=your_gemini_key
GEMINI_IMAGE_MODEL=gemini-2.5-flash-image

# OpenAI (needed if IMAGE_PROVIDER=openai)
OPENAI_API_KEY=your_openai_key

# --- ImageKit (required) ---
IMAGEKIT_PRIVATE_KEY=your_private_key
IMAGEKIT_PUBLIC_KEY=your_public_key
IMAGEKIT_URL_ENDPOINT=your_url_endpoint

# --- Auth ---
JWT_SECRET_KEY=generate_a_long_random_string
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

Start the API:

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

API docs are then available at **http://localhost:8000/docs**.

### 3. Frontend setup

```bash
cd FRONTEND
npm install
```

Create a `.env` file inside `FRONTEND/`:

```env
VITE_API_BASE_URL=http://localhost:8000
```

Start the dev server:

```bash
npm run dev
```

Open **http://localhost:5173**, create an account, and generate your first thumbnail.

## 🔌 API Overview

Base URL: `http://localhost:8000` — all `/api/*` routes require `Authorization: Bearer <token>`.

| Method | Endpoint | Description |
|---|---|---|
| POST | `/auth/signup` | Create an account `{ email, password }` → `201` |
| POST | `/auth/login` | Login, returns `{ access_token, token_type }` |
| POST | `/api/upload_headshot` | Upload headshot image → `{ url }` |
| POST | `/api/job` | Create generation job → `{ job_id }` (instant) |
| GET | `/api/job/{job_id}` | Snapshot of a job + its thumbnails |
| GET | `/api/job/{job_id}/stream` | SSE stream: `thumbnail_ready` / `thumbnail_failed` / `job_completed` |

### SSE event flow

```
GET /api/job/{id}/stream   (Authorization: Bearer <token>)

event: thumbnail_ready   data: { thumbnail_id, style_name, imagekit_url, variants }
event: thumbnail_failed  data: { thumbnail_id, style_name, error }
event: job_completed     data: { job_id, status: "completed" | "failed" }
```

> The browser-native `EventSource` API cannot send custom headers, so the frontend uses `@microsoft/fetch-event-source` for the live stream.

Full request/response examples and the complete error catalogue live in [`BACKEND/ARCHITECTURE.md`](BACKEND/ARCHITECTURE.md).

## 🔄 How It Works

1. **Upload** — the headshot is uploaded to ImageKit and its URL is stored.
2. **Create job** — `POST /api/job` creates one `Job` row and 1–3 `Thumbnail` rows (each assigned a style: bold & dramatic, clean & minimal, vibrant & energetic). The API responds instantly.
3. **Background processing** — `process_job()` downloads the headshot, runs the configured AI provider (with automatic fallback to the next provider), and uploads the generated PNG to ImageKit.
4. **Real-time updates** — the SSE stream pushes each finished thumbnail to the job page; the UI fills in results live with a spinner for pending items.
5. **Variants** — ImageKit transform URLs (`?tr=w-1280,h-720,...`) provide YouTube, Shorts, and square crops with smart focal-point cropping.
